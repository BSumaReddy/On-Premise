Overview

What is Semgrep?

Semgrep (Semantic Grep) is an open-source Static Application Security Testing (SAST) tool. It scans source code without executing it to detect security vulnerabilities, hardcoded secrets, and dangerous coding patterns — before they reach production.

Tool TypeWhat It ChecksUsed Here?
Linters (flake8, pylint)Code style, syntax errors—
Semgrep (SAST)Security vulnerabilities, hardcoded secrets, dangerous APIs✅ Yes
Dependency Scanners (snyk)Vulnerable third-party libraries—

Why We Use It

BenefitDescription
🔍 Finds secrets earlyDetects hardcoded tokens before they reach git history
🤖 Fully automatedRuns on every push and pull request via GitHub Actions
📊 Tracks progressShows fixed vs new issues across every pipeline run
🔗 Backend reportingSends results to our dashboard via REST API after every scan
⚙️ Zero configuration--config auto auto-selects rules based on detected languages

Step-by-Step Explanation

①
Checkout Code
Clones the repository into the GitHub Actions runner (Ubuntu VM). All source files are now available for scanning on the runner's filesystem.
uses: actions/checkout@v4
②
Setup Python 3.10
Semgrep is a Python-based CLI tool. Python 3.10 must be installed on the runner before Semgrep can be installed and executed.
uses: actions/setup-python@v5
with:
  python-version: "3.10"
③
Install Semgrep
Downloads and installs the Semgrep CLI from PyPI. This is the scanning engine that analyzes all source files.
run: pip install semgrep
④
Download Previous Report KEY STEP
Downloads report.json from the previous workflow run's artifact storage. This is what enables comparison between runs. On first run, no artifact exists — the step warns and continues.
uses: dawidd6/action-download-artifact@v6
with:
  name: semgrep-report
  path: previous_report
  if_no_artifact_found: warn
continue-on-error: true
ℹ️
Why dawidd6 and not the official action? GitHub's official download-artifact can only download artifacts from the same run. dawidd6/action-download-artifact can download from previous workflow runs — which is required to compare scan results.
⑤
Run Semgrep Scan CORE SCAN
Executes the full security scan against all non-ignored files and saves results to report.json.
run: semgrep scan --config auto --json -o report.json || true
FlagMeaning
--config autoAuto-detect languages, download matching rules from semgrep.dev
--jsonOutput in machine-readable JSON format
-o report.jsonSave output to report.json
|| trueDon't fail the pipeline even when findings exist
⑥
Show Report
Prints the raw report.json to GitHub Actions log output so developers can review findings directly in the CI interface without downloading artifacts.
run: cat report.json
⑦
Compute Fixed and New Findings KEY STEP
Inline Python script that loads both reports, computes set differences, writes diff_report.json, and prints a human-readable summary to logs.
python3 - <<'EOF'
  # Loads previous_report/report.json  (last run)
  # Loads report.json                   (current run)
  # fixed      = previous - current     (resolved issues)
  # new        = current  - previous    (new issues)
  # persistent = previous ∩ current     (still open)
  # Writes → diff_report.json
  # Prints → summary to Actions log
EOF
⑧
Upload Current Report as Artifact
Saves report.json to GitHub Artifacts, overwriting the previous one. This report becomes the "previous" baseline for the next pipeline run — completing the memory cycle.
uses: actions/upload-artifact@v4
with:
  name: semgrep-report
  path: report.json
  overwrite: true
⑨
Upload Diff Report as Artifact
Saves diff_report.json as a separate artifact. Downloadable under Actions → Run → Artifacts in GitHub UI.
uses: actions/upload-artifact@v4
with:
  name: semgrep-diff-report
  path: diff_report.json
⑩
Send Reports to Backend
POSTs both reports to the BanyanCloud backend API. Pipeline does not fail if backend is unreachable (|| true).
curl --max-time 10 -X POST "${BACKEND_URL}/api/scan/upload" \
  -H "Content-Type: application/json" \
  -d @report.json || true

curl --max-time 10 -X POST "${BACKEND_URL}/api/scan/diff" \
  -H "Content-Type: application/json" \
  -d @diff_report.json || true

Semgrep Scan — How It Works

What --config auto Downloads

Semgrep detects Python + YAML files in the repo and auto-downloads matching rule packs:

Rule PackWhat It Checks
p/pythonPython-specific vulnerabilities (eval, pickle, exec, unsafe patterns)
p/secretsHardcoded tokens, API keys, passwords, JWT tokens
p/owasp-top-tenOWASP Top 10 vulnerability patterns
p/security-auditGeneral security anti-patterns across languages
p/github-actionsInsecure workflow configurations in YAML files

Files Scanned in This Project

✅  Scanned:
    .github/workflows/semgrep.yml
    app.py
    on_premise/**/*.py          (all Python source files — 25+ files)
    requirements.txt
    README.md

🚫  Skipped (via .semgrepignore):
    environment.env
    *.env
    logs/
    __pycache__/
    *.pyc

How Semgrep Matches Patterns

Semgrep uses AST (Abstract Syntax Tree) matching — not simple text search or regex. It understands code structure:

ApproachBehavior
Text/Regex searchFinds eyJ anywhere in any file, including comments, strings, docs
Semgrep (AST)Finds JWT patterns specifically in variable assignments, understands context — not just text

Every scan produces a report.json file. Here is the annotated structure:

{

  "results": [                   // All findings — empty [] = clean scan
    {
      "check_id": "generic.secrets.security.detected-jwt-token",
                                 // Unique rule ID that triggered
      "path": "environment.env", // File where the issue was found
      "start": {
        "line": 50,              // Exact line number
        "col": 17,               // Column start
        "offset": 1362           // Byte offset in file
      },
      "extra": {
        "message": "JWT token detected",  // Human-readable description
        "severity": "ERROR",              // ERROR / WARNING / INFO

        "metadata": {
          "category":    "security",
          "confidence":  "LOW",
          "likelihood":  "LOW",
          "impact":      "MEDIUM",
          "cwe":   ["CWE-321: Use of Hard-coded Cryptographic Key"],
          "owasp": ["A02:2021 - Cryptographic Failures"],
          "technology":  ["secrets", "jwt"],
          "subcategory": ["audit"]        // audit = requires human review
        },

        "fingerprint": "unique-hash",     // For deduplication across runs
        "engine_kind": "OSS"
      }
    }
  ],

  "errors":  [],                 // Parser errors — empty = successful scan

  "paths": {
    "scanned": ["app.py", ...]   // Every file that was checked
  },

    }
  }
}

Diff Engine — Tracking Fixed Issues

This is the core feature that turns Semgrep from a simple scanner into a security progress tracker across every CI run.

The Algorithm

# Each finding is fingerprinted as a unique composite key:
key = f"{rule_id}|{file_path}|{line_number}|{message}"

# Example key:
"generic.secrets.security.detected-jwt-token|environment.env|50|JWT token detected"

# Set operations determine the status of each finding:
fixed      = previous_findings - current_findings   # ✅ were present, now gone
new        = current_findings  - previous_findings  # 🆕 appeared for first time
persistent = previous_findings ∩ current_findings   # ⚠️ still unresolved

diff_report.json Structure

{
  "total_current":       0,
  "total_previous":      2,
  "new_findings":        0,
  "fixed_findings":      2,      // ✅ issues resolved since last run
  "persistent_findings": 0,

  "fixed": [
    "generic.secrets...|environment.env|50|JWT token detected",
    "generic.secrets...|recs_connector.py|25|JWT token detected"
  ],
  "new": []
}

GitHub Actions Log Output

  Current  findings : 0

  🆕 New             : 0
  ⚠️  Persistent      : 0

  [generic.secrets.security.detected-jwt-token] environment.env:50 — JWT token detected
  [generic.secrets.security.detected-jwt-token] recs_connector.py:25 — JWT token detected

Memory Between Runs via Artifacts

Run 1 (Monday) Scan → 2 findings Upload → artifact "semgrep-report" saved ────────────────────────┐ │ Run 2 (Tuesday — fix applied) │ Download ◄── artifact "semgrep-report" ──────────────────────────┘ saved as previous_report/report.json Scan → 0 findings Diff → fixed=2, new=0 ✅ Upload → artifact updated ──────────────────────────────────────┐ │ Run 3 (Wednesday — new code pushed) │ Download ◄── artifact "semgrep-report" ─────────────────────────┘ Scan → 1 new finding Diff → new=1 ⚠️ team is immediately alerted

.semgrepignore — Scan Exclusions

Located at the project root. Syntax is identical to .gitignore. Semgrep reads this file before scanning and skips all matching paths.

# Env files contain runtime secrets — skip scanning them
# (already gitignored, but Semgrep scans physical files by default)
*.env
environment.env

# Log files — not source code, may contain captured token values
logs/

# Python bytecode — not human-readable source
__pycache__/
*.pyc

Why .env Files Must Be Excluded

❌
Without .semgrepignore: Semgrep scans every file physically present on disk — including environment.env. Even though it's gitignored (not committed), it exists on the runner and is scanned, causing false positives for secrets that are intentionally stored there.
✅
With .semgrepignore (*.env rule): Semgrep skips environment.env entirely. The JWT finding disappears from the scan results.

How to Add More Exclusions

# Specific file
sensitive_config.json

# Entire folder
migrations/
tests/fixtures/

# File extensions (certificates, private keys)
*.pem
*.key
*.p12
*.pfx

Inline Suppression (Per Line)

# Add # nosemgrep at end of any line to suppress that specific finding only
DEFAULT_TOKEN = os.getenv("RECS_TOOL_TOKEN", "")  # nosemgrep

Backend Integration

GitHub Secret Setup

Navigate to: GitHub Repo → Settings → Secrets and Variables → Actions → New repository secret

Secret NameValue
BACKEND_URLhttps://your-backend-domain.com (no trailing slash)

Endpoint 1 — Full Scan Report

POST /api/scan/upload
Content-Type: application/json
Body: report.json  (full Semgrep output)

Handler in app.py:

@app.post("/api/scan/upload")
async def upload_scan(request: Request):
    """Receive Semgrep scan report from GitHub Actions CI pipeline."""
    data    = await request.json()
    results = data.get("results", [])
    errors  = data.get("errors",  [])
    return {
        "status":    "received",
        "findings":  len(results),
        "errors":    len(errors),
        "timestamp": datetime.utcnow().isoformat()
    }

Response:

{ "status": "received", "findings": 0, "errors": 0, "timestamp": "2026-05-27T10:30:00" }

Endpoint 2 — Diff Report

POST /api/scan/diff
Content-Type: application/json
Body: diff_report.json  (fixed/new/persistent summary)

Used for: Trend charts, alerting when new issues appear, fix rate tracking in the security dashboard.

curl Flags Explained

Custom Rules

Create project-specific rules in semgrep-rules/custom.yml:

rules:

  # Block print statements — use logger instead
  - id: no-print-statements
    pattern: print(...)
    message: "Use logger.info() instead of print() for consistent log management"
    languages: [python]
    severity: WARNING

  # Detect hardcoded internal IPs
  - id: no-hardcoded-ips
    patterns:
      - pattern: $X = "172.16.$A.$B"
      - pattern: $X = "10.0.$A.$B"
    message: "Do not hardcode IP addresses — use environment variables"
    languages: [python]
    severity: ERROR

  # Enforce Bearer token from env only
  - id: no-hardcoded-bearer-tokens
    pattern: $VAR = "Bearer $TOKEN"
    message: "Bearer tokens must not be hardcoded — use os.getenv()"
    languages: [python]
    severity: ERROR

  # Require timeout on all HTTP requests
  - id: requests-no-timeout
    pattern: requests.get($URL)
    message: "Always specify timeout= in requests.get() to prevent hangs"
    languages: [python]
    severity: WARNING

Enable in Pipeline

# semgrep.yml — update the scan step:
- name: Run Scan
  run: semgrep scan --config auto --config semgrep-rules/ --json -o report.json || true

Troubleshooting

❓ "No previous artifact" warning on every run

ℹ️
Cause: First run ever, artifact expired (90-day retention), or workflow renamed.
Fix: Expected on first run. continue-on-error: true handles it gracefully. Diff will show previous=0.

❓ False positive — safe code is being flagged

# Option A — Inline suppression (specific line)
DEFAULT_TOKEN = os.getenv("RECS_TOOL_TOKEN", "")  # nosemgrep

# Option B — Rule-level suppression
# nosemgrep: generic.secrets.security.detected-jwt-token
DEFAULT_TOKEN = os.getenv("RECS_TOOL_TOKEN", "")

Or add the file/folder to .semgrepignore.

❓ Backend POST not receiving data

  1. Confirm BACKEND_URL secret is set: GitHub → Repo → Settings → Secrets → Actions
  2. No trailing slash: https://example.com ✅ not https://example.com/ ❌
  3. Backend must be accessible from GitHub Actions public IP ranges
  4. Backend must accept Content-Type: application/json
  5. Check pipeline logs — curl response is printed even with || true

❓ Scan is slow or times out

# Use targeted rule packs instead of full auto
semgrep scan --config p/python --config p/secrets --json -o report.json || true

# Only scan ERROR severity findings
semgrep scan --config auto --severity ERROR --json -o report.json || true

❓ Too many findings / noisy results

# Add to .semgrepignore
tests/
migrations/
scripts/
docs/
